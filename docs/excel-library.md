# Excel 长期管理

本页说明 rc.7 开发版的新固定格式，锁定 A rc.6 引擎；已发布 B rc.6 仍使用旧格式。安装新版并迁移后才能使用新表。

## 三个业务页

- **文献**：一行一篇，先显示分类、人工阅读进度、课题关系、下一步与 PDF / Reader / 成果入口；作者和双语摘要等长字段可展开。
- **阅读成果**：复用已发布 Reader 的研究问题、方法、关键结论、局限，以及已确认记录。AI 导读标为待核对，确认记录保留依据类型与证据状态。父子会话 ID 不再占据用户视野。
- **图表索引**：按当前 PDF 的图表清单组织原图、结构表格和原文入口。同一逻辑表的截图与 HTML 同行；只有明确引用该图表证据块的记录才显示关联。

缺少导读、图表或文件时显示未生成 / 未就绪；不额外调用模型补写科学结论。原文定位有效不等于科学结论已经证明。

## 六个个人字段

| 列名 | 保存的内容 |
| --- | --- |
| 阅读进度 | 未读、在读、已读、待复读；生成 Reader 不会自动变成已读 |
| 与课题的关系 | 为何收藏，对哪个研究问题有帮助 |
| 下一步 | 复读、核对、比较或实验计划 |
| 个人理解程度 | 自由文本，保留尚不理解的部分 |
| 个人思考 | 个人判断、假设与解释边界 |
| 用户笔记 | 摘录、备忘与其他记录 |

黄色六列支持回写。系统字段由引擎维护；Excel 中改题名、分类或路径不会改库。分类与标签继续通过 Codex 管理。

可以用整张表的筛选和排序；不要仅移动部分列、删除论文行或改隐藏身份。个人更新时间只在个人字段实际变化时更新。课题关系和笔记支持关键词检索；Codex 可按阅读进度、最近个人维护时间筛选。

## 保存与同步

保存并关闭表格软件，在 Codex 中说“同步文献表”。Skill 使用正式 `excel_sync` 接口；返回 `status=success`、导入论文数 `updated`、导出论文数 `rows`、时间 `exported_at` 和路径 `path`。

`pending` 表示仍需处理文件占用或冲突，不能宣称同步完成。不会自动删除占用标记。Windows 能否选中论文行取决于本机 Excel；macOS/Linux 使用默认应用打开，并提供行号供查找。

同步逐字段比较导出基线、Excel 和数据库：表未改保留库内新值；仅表改动才回写；同样的新值不冲突；不同修改保留双方并报告。显式清空算修改。冲突批次不部分回写，原表保持不变；处理时依据用户选择，不猜哪份较新。

通过 Codex 修改个人记录也走固定白名单：先读 `item`，再用 `personal_update` 携带旧值 `expected` 提交。冲突先重新读取，不能改用 SQL 绕过检查。完整请求见 [Skill API](../skills/deep-literature-for-codex/references/api.md)。

## 旧表、备份与换机

数据库 v5 迁移先创建可验证的 SQLite 备份。旧表没有导出基线：可确定的三列旧记录会保留；旧表与现有非空库值不同则暂停，不自动覆盖。

每次替换前把原工作簿按内容哈希归档到文献根的 `backups/xlsx`。退出的旧占位列、额外手填页和自建列保存在原表归档中，不进入六字段回写。导出遇到超长单元格会失败并保留原表，不静默截断。

换机要保存并同步后，通过 `library-backup` 备份整个文献库，再按 [生命周期指南](lifecycle.md) 恢复。数据库内的导出基线、PDF、Reader 和路径关系一起保留；单独复制 XLSX 不能代替备份。OAuth / MinerU 密钥需在新机配置。

## 验证边界

自动回归覆盖排序归属、三方冲突、清空、旧格式迁移、完整目录恢复和文件占用。原生应用结果按平台记录；Windows Excel 成功不能替代 macOS Excel、Numbers 或 Linux LibreOffice 的实际编辑回写测试。
