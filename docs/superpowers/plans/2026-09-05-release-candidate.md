# 双项目 0.1 候选收口执行记录

用户在 2026-09-05 晚间授权直接开展不冲突工作，随后确认“工程”已完成，并希望翌日有可发布候选。本任务持续推进到可验证交付；真实登录与未满足的发布条件如实记录，不将开发阶段包冒充完整正式版。公开推送/发布留在用户验收之后。

## 并行工作边界

- 父任务：B 独立运行、生命周期、浏览器、接入集成、发行包、总体验收。
- `a_release_boundary`：A PA-01 / PA-03 源码、回归与候选包；保留 A 全部在途成果。
- `oauth_adapter`：只写 B `oauth/` 和 `docs/oauth.md`，选定/固定已有订阅接入并验证未登录/协议生命周期。
- `handoff_contract`：只读 A/DSH 现有接口，提供 PB-05/06/07/11 的精确最小合同；只写自己的文档/探针。

任何跨边界改动先在任务内协调，统一由父集成。最终包使用固定 tarball、wheel、运行版本与 SHA，既有用户 DSH/账号/文献不作为测试夹具。

## 收口顺序与判据

- [ ] B 在 Windows 中文路径干净安装，无全局 DSH 前提；官方 npm 包启动正常。
- [ ] B 实例身份、重复/并发启动、停止/重启、3080 共存、真实内置浏览器通过。
- [ ] A OA-only 和精简设置页完成；全套回归、真实 tarball 安装和内容验收证据按最终包对齐。
- [ ] B 分类会话持久绑定、幂等交接、任务/资产读回完成；受限会话不能越界或通过全局工具绕过。
- [ ] B 原生模型设置与所选 OAuth 接入完成；未登录/取消/退出/额度不可用均真实表达；本人登录是用户操作。
- [ ] B 安装/升级/回退/卸载的数据保留边界实现并验证；手动 PDF 兜底通过 A 导入。
- [ ] 独立规范审查、代码审查、同一候选包综合验收与发布资料一致。
