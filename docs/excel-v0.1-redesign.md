# v0.1 Excel 长期管理重构

日期：2026-09-07。状态：现状审查和[隔离 Demo](../demos/excel-v01/README.md)经用户确认，正式引擎、版本迁移及 Codex 接口已整合到 rc.7 开发版。具体通过项目见 [整合验收](excel-v0.1-acceptance.md)；已发布 rc.6 不据此宣称获得新能力。

用户已明确：研究问题、方法、关键结论与证据、局限、与课题的关系、阅读进度、个人笔记都要保留；这些属于 v0.1 的基本管理能力。字段自定义、模板自定义和跨文献 chat 总结仍放在 v0.2。

## 1. 要解决的实际问题

文献越积越多后，用户应能回答：当初为什么收藏它，它研究什么，证据在哪里，我如何理解它，接下来要做什么。Excel 应支持这个过程，并能在更换聊天、重新解析、升级和换机后继续使用。

以文献和阅读成果组织数据。会话只是产生讨论的渠道，不是长期记录的身份。SQLite 仍是事实源，Excel 是持续更新、可回写明确个人字段的工作表。

## 2. 当前实现的核对结果

审查对象：B rc.6 固定的 A 引擎提交 `8e00b334389cd90721b7d404013a07687753aa5c`。使用该提交在独立合成库生成工作簿，检查导出、回写和行重排；没有改动用户文献库。

| 现状 | 对长期管理的影响 |
| --- | --- |
| 文献表共 29 列；主要研究单位、影响因子、学科领域、主要内容、解决方法、实验假设、创新、不足之处共 8 列固定输出为空 | 既占据视野，又让用户误以为这些能力已经存在 |
| 精读结果已有研究问题、关键方法、核心结果、局限及原文块引用，Excel 没有读取 | 读过的成果留在 Reader 内，无法在总表积累和比较 |
| 只回写个人思考、个人理解程度、用户笔记；未提供独立课题关联、人工阅读进度和下一步字段 | 个人记录缺少组织方式，三个文本框无法覆盖日常管理 |
| “阅读状态”导出的是内部处理状态，如 `full_read_ready` | Reader 生成进度与用户真正的阅读进度没有分清 |
| “整理结论”把父会话 ID、整理子会话 ID 放在前列；没有导出已有的依据类别与证据状态 | 用户看到内部实现信息，却不容易区分原文依据、个人判断和待核对内容 |
| “图表资产”前列是文献 ID、资产 ID，后面主要是图注和长路径 | 可以定位文件，但不清楚图表与阅读结论的关系 |
| 仅冻结表头，未冻结文献名；同步身份绑定物理行号，整行交换后返回身份冲突 | 横向滚动容易失去论文身份，正常排序也不能用于日常管理 |
| 回写笔记不更新个人维护时间，也未进入现有文献搜索索引 | 很难找回最近整理的论文，或者通过自己写过的判断检索论文 |

另做了一项冲突实验：导出旧笔记后，直接在合成 SQLite 中模拟第二个写入方保存新笔记，再刷新未编辑的旧 Excel。刷新返回 `success`，新笔记被旧表覆盖。这证明当前同步缺少导出基线比较；它不等于当前 Codex 已有第二个笔记写入入口。为支持未来通过 Excel 和 Codex 共同维护个人记录，v0.1 必须先解决此问题。

此前的身份冲突丢笔记问题在当前源码中已改为 `pending` 并保留原表，本轮也验证了保留行为。不能把这个已修复的问题和上述新发现的旧快照覆盖问题混为一谈。

父子会话目前仍参与内部 Review 调用。此次应移除的是它们在 Excel 中的主导地位，保留已有结论和来源关系；不趁此更换 v0.1 的 DSH 会话实现。

## 3. 建议的固定工作簿

保留三个业务页和一个简短说明页。具体列宽等随样表验收调整，不新增自定义设置系统。

| 工作表 | 用户目的 | 每行代表什么 |
| --- | --- | --- |
| 文献 | 筛选、安排阅读、记录个人判断、打开成果 | 一篇文献 |
| 阅读成果 | 回顾研究问题、方法、结论、局限及证据 | 一条有类别和来源的阅读记录 |
| 图表索引 | 找到某篇论文的某张图表并回查证据 | 一项逻辑图或表，而非一个导出文件 |
| 说明 | 清楚知道如何保存、同步、处理冲突与备份 | 简短操作说明和本次同步信息 |

### 文献页

默认视野优先显示文献名、分类、阅读进度、与课题的关系、下一步和 PDF / Reader / 阅读成果入口。年份、期刊、标签支持筛选；作者、标识符、双语摘要和长笔记保留在后续分组列，避免把所有长文本挤在首页。横向滚动时始终保留文献名。

个人记录固定包含：

- **与课题的关系**：为什么收藏、可以支持哪个问题或采用什么方法。由用户维护；Agent 可以提出建议，不自动写成用户立场。
- **阅读进度**：未读、在读、已读、待复读等固定状态。由用户设置，生成 Reader 或点击打开文件不能自动变成“已读”。
- **个人理解程度**：保留已有自由文本，描述还有哪里没理解。与阅读进度分别保存，不强制把旧文本映射成状态。
- **个人思考、用户笔记**：完整保留两个现有字段，不在迁移时擅自合并。界面说明各自用途，避免用户不知道该写在哪里。
- **下一步**：例如核对一个对照组、复读某段、比较另一篇文献、尝试某种方法。
- **个人记录更新时间**：真正修改上述内容才变化，与后台下载或解析更新时间分开。

处理进度另显示为“缺 PDF / 处理中 / Reader 可用 / 需处理”等用户可理解的状态。影响因子、单位等没有可靠填充能力的占位列退出默认表；已有题录信息和旧表手填内容不得因此删除。

### 阅读成果页

将当前“整理结论”改为按文献归属的阅读成果。可见列以“论文、记录类别、内容、依据类型、确认状态、证据位置、打开原文、更新时间”为主；会话 ID 和内部记录 ID 留在内部溯源数据。

初始内容复用当前 PDF 版本下的 `reading_guide.json`：研究问题、关键方法、核心结果、局限。保留原文块引用，并与该版本的 PDF / source map 对应。不额外再调用一次模型为 Excel 重复分析论文。

已有用户确认结论也进入此页，按 `paperId` 汇集，保留其原始记录身份。AI 导读与用户确认内容分别展示来源和状态，不凭相似文字合并；同一文献在不同会话下产生的记录也不能因会话变化丢失。

“AI 归纳”“原文摘录”“个人判断”“待解决问题”应能区分。证据定位有效，只表示能回到相应位置，不等于该位置已经证明结论。未生成、某类别未提供、原文确实未说明是不同情况，不能用一个空白或统一的“原文未说明”替代。

用户可以先使用标为“待核对”的 AI 导读，不要求逐条确认所有记录后才能管理文献；正式确认的结论仍走已有确认流程。重新解析后保留个人记录和旧确认结果，旧证据失配时标为需重新核对，不自动绑定到新 PDF。

### 图表索引页

该页应先回答三个问题：这是哪篇论文的哪张图，它与什么阅读结论相关，我怎样回到原图核对。

建议可见列顺序：

`论文 → 原文图表编号 → 类型 → PDF 页码 → 图注 → 关联阅读结论 → 原图 / 结构表格 / 原文入口`

- 图号优先采用能核实的原文编号，如 Fig. 2、Table 1；识别不出时显示页码与“图号待核对”，不把 MinerU 内部资产 ID 当成原文编号。
- 同一张表的截图与结构化 HTML 放在同一行；分图合并关系未经识别时不假装已还原为完整 Figure。
- 图注与图意解读分别对待。只有明确指向该图表的导读证据或已保存结论才显示关联，不能把整篇论文结论机械复制到每张图旁。没有关联时显示“未建立解读关联”。
- 先保证清楚的图表身份和可用的查看入口。v0.1 不新增逐图 AI 解读、自动关键图筛选，也不把所有原尺寸图片嵌进工作簿。
- 缺少、过期或未经确认的图表与结构化表格要显示状态；不能用可点击的旧路径冒充当前有效成果。
- 文献页可跳到该论文的图表区域，此页可返回论文。长路径、哈希和内部 ID 不占据默认阅读视野，溯源数据继续保留。

这使图表索引和阅读成果互相补充：前者找图、回查，后者保存理解与结论。

## 4. 同步与长期保存合同

这部分是 v0.1 的发布要求，不能只换表头和配色。

1. **以稳定文献身份同步。** 使用 `paperId` 与可核对的行身份关联记录，行号仅用于定位；整张表排序、筛选、追加新文献不影响笔记归属。重复、缺失或不匹配的身份必须保留原表并报告。
2. **只导入真实改动。** 保存上次导出基线，逐字段比较“基线、当前 Excel、当前 SQLite”。表未改则保留库内新值；只改表则导入；两边修改为相同值可合并；不同修改进入明确冲突处理。
3. **显式清空也算修改。** 不用“非空优先”吞掉用户删除内容的意图；旧表空值也不能清空较新的库内笔记。
4. **冲突可恢复。** 保留原工作簿和各方内容，报告具体论文与字段；不靠整行覆盖或最后写入时间猜测用户意图。
5. **Excel 与 Codex 共用个人记录服务。** 不提供任意 SQL 或任意字段回写；扩展固定白名单，并沿用文献作用域校验。两个入口都更新个人维护时间与检索索引。
6. **维护记录能被找回。** 课题关联、个人笔记和阅读成果进入带内容类型的检索；支持按阅读进度、分类、标签及个人维护时间查看。暂不引入向量库或新的推荐系统。
7. **同步状态可见。** 提供明确的同步入口和结果：导入多少条个人改动、是否有冲突、是否仍被 Excel 占用、是否已经完成导出。不能依靠一段隐藏的手工 Python 命令完成日常管理。
8. **普通排序可实际使用。** 身份校验从行号转为稳定键后，还要选择兼容原生排序的表格保护方式；不能只打开一个保护标志就宣称 Excel 可以排序。系统字段仍不从 Excel 回写。
9. **升级与备份保留内容。** 先保留旧库和旧表，再导入可确认身份的三列旧笔记，迁移到新固定格式。无法映射的历史内容报告并保留，不静默丢弃。恢复备份后继续可编辑、可刷新。

## 5. 实施顺序

| 顺序 | 工作 | 主要落点 | 完成条件 |
| --- | --- | --- | --- |
| 1 | 固定个人字段、基线合并与迁移 | A schema、个人记录服务、`xlsx_snapshot` | 先通过旧表迁移、排序归属、双方修改冲突与清空回归 |
| 2 | 接入已有精读成果并整理图表索引 | A 导读 / 证据接口及 Excel 导出 | 同一 PDF 版本的导读、已确认结论、图表及链接逐项对上 |
| 3 | 补齐操作与检索入口 | A 文献检索和同步入口；B Codex 命令与 Skill 指引 | 用户能够通过正常对话维护和查询，不依赖手工 SQL |
| 4 | 样表与原生应用验收 | 当前引擎生成的工作簿，Excel / LibreOffice | 实际完成编辑、整表排序、刷新、重新打开、从总表回查证据 |
| 5 | 固定交付包 | A 引擎包与 B 锁定依赖、升级测试、使用文档 | 安装包运行结果和已验收源码一致，再讨论新版候选发布 |

生成工作簿的库继续沿用现有实现，不为此次重构更换技术栈。A 的共享引擎改动也需保持原生插件可用；B 不能只改文档和 Skill，而继续装旧引擎。

## 6. v0.1 验收场景

- 混合未取得 PDF、处理中、Reader 就绪、已读和待复读的文献：系统处理状态不改变人工阅读进度。
- 研究问题、方法、结论和局限能由已存在的导读进入 Excel；缺项如实标记，无凭空填写。
- 同一论文的图、表格截图和 HTML 结构表能够正确识别、合并和打开；图表关联的结论具有明确依据。
- 写入中文长笔记与课题关联，保存关闭，新增论文、整表排序，再刷新与重启：内容与文献归属不变。
- 库内修改、Excel 修改、双方相同修改、双方冲突、主动清空和旧副本分别验证，不允许静默覆盖。
- 通过个人笔记中的独有关键词和最近维护时间找回论文，确认后台任务没有伪造“最近阅读”。
- 替换 PDF 或重建 Reader 后，旧笔记保留、旧证据明确标记，失效路径不冒充当前证据。
- 旧版本升级、完整备份及新目录恢复后，记录仍可编辑回写，PDF / Reader / 图表导航可继续使用。
- 至少完成 Windows Excel、macOS Excel、Linux LibreOffice 各自的实际可用性核对；程序性 XLSX 检查与真实桌面结果分别记录，未覆盖的平台不写“全部通过”。

## 7. 本轮证据与范围

本轮完成了当前源码阅读、原生生成器的合成库实验和实际导出表格的只读检查。确认：29 列及会话字段布局；整行重排会进入 `pending` 且保留原表；个人笔记不进入现有检索、不更新个人维护时间；旧快照可覆盖模拟的库内新笔记。以上为重构前的只读审查结果。用户确认 Demo 后，新结构已进入生产引擎和 Codex 接口；当前结果以 [整合验收记录](excel-v0.1-acceptance.md) 为准。真实账号及科学内容质量验收独立记录。
