# v0.2 技术路线

更新：2026-09-07。本文记录已确认的产品方向与待实现事项，不代表当前版本已经提供这些能力。v0.1 继续采用现有分类主管模式。

## 核心调整：每篇文献一个 chat

DSH 从“每个分类对应一个主管会话”调整为“每篇文献对应一个持久 chat”。单篇 chat 负责该文献的精读、问答与讨论；分类保留为组织和筛选文献的方式。Codex 继续承担整个文献库的总管理员职责。

同一实例内以文献的稳定 `paperId` 绑定 `sessionId`，不以标题或分类名识别会话。重复入库经去重后应复用已有文献 chat；改标题、移动分类或重启实例不应丢失会话关系与历史。文献与资产仍以现有 SQLite 文献库为事实源。

## 多选 chat，由 Codex 跨文献总结

用户选择多个文献 chat，并指定总结问题；Codex 读取所选会话及其对应文献上下文，完成跨文献总结，例如共同发现、方法差异、结论冲突和仍待解决的问题。选择可以跨分类，分类不再限制总结范围。

总结必须保留文献和会话来源；涉及论文事实时应能回查原文证据，不能把 chat 中的模型推测或用户讨论直接当作论文结论。读取不完整、证据缺失或上下文被截断时，应明确说明总结覆盖范围。只读取用户选中的会话；需要扩大范围时由用户调整选择。

## 实现顺序与验收

| 阶段 | 待实现内容 | 验收标准 |
| --- | --- | --- |
| 单篇会话绑定 | 将分类主管绑定改为文献与会话绑定，调整交接和工具作用域 | 一篇文献对应一个主 chat；重复导入、重启和移动分类后可续接；单篇会话不能误改其他文献资产 |
| 会话选择与读取 | 提供多选入口，向 Codex 返回所选文献身份、会话历史和证据引用 | 可跨分类选择；返回内容与所选 chat 一致；长历史的分页或截断状态明确可见 |
| 跨文献总结 | Codex 根据用户问题汇总所选会话，并保留来源 | 能区分各论文观点与讨论推测；不混入未选会话；结论可追溯到对应文献和证据 |
| 旧数据迁移 | 设计 v0.1 分类会话向单篇会话的过渡方式 | 保留原文献库、资产和历史；不能将旧分类会话中的混合讨论错误归属到某篇论文 |

旧分类会话如何保留入口、如何衔接已有单篇 Review，以及多选入口的具体交互，留到 v0.2 实现设计时确定。本次只记录路线，不改动 v0.1 会话合同或运行行为。

## 已记录的其他 v0.2 事项

Excel 的固定字段长期管理、已有精读成果接入、图表索引和笔记安全同步属于 [v0.1 重构范围](excel-v0.1-redesign.md)，不推迟到 v0.2。下表中的 Excel 自定义指用户自定义字段与展示方案。

| 事项 | 范围 |
| --- | --- |
| Excel 字段自定义 | 用户选择文献表展示的信息；SQLite 继续作为事实源，展示字段与允许回写的字段分别定义 |
| HTML 模板自定义 | 用户可选择或自定义精读页面模板，保留原文、译文与证据定位关系 |
| 文献雷达 | Agent 帮助用户确认研究方向，并发现方向相关的优质文献；具体来源、筛选依据和触发方式待设计 |

上述事项均待实现；本路线不改变当前版本的安装、模型接入和文献获取边界。
