# macOS 首次实装报告与跟进

来源：用户于 2026-09-07 提供的 macOS 首次运行复盘报告。以下真实运行结果由用户在另一台机器记录，本轮开发没有重新操作该 Mac。

## 已获得的证据

MacBook Air / Apple Silicon，macOS 26.6.2；安装 B rc.5 / A rc.4 / DSH rc.7，使用 gpt-5.6-luna / high 和真实 MinerU API。PMID 40835971 完成 27 页解析、229 个正文块、52 个图像资产、8 个表格资产、7 个翻译批次、259 个翻译块、Reader 和一行 Excel。

PDF 与 Reader 声明的来源 SHA 一致。端到端约 2 小时 50 分，包含等待、现场空图表修补、provider 重启和模型 JSON 修正，不能当作纯推理耗时，也不能称为无人工干预的全新安装成功。

## 处理记录

| 问题 | 当前处理 | 还需要的验收 |
| --- | --- | --- |

| 首次使用误以为继承外层 Codex 登录 | 开发版入口显示独立模型配置步骤、订阅按钮、MinerU 保存/实调区别；start/status 返回 entryUrl，Skill 首次停留引导页 | Mac 新实例首次点击到授权页；当前尚非带四项实时状态的完整向导 |
| Excel 成功仍显示待同步 | 新引擎导出更新库中状态及状态文件，job-status 汇总实际子作业回执；B 正式同步 API | Mac 打开占用→pending→关闭重试→success，实际表格与回执一致 |

| waiting_agent 多次手动续接 | 已接收的译文持久保留，只补剩余块；本批初次提交后最多两次补试，随后等待用户继续 | 本机重启后仍保持暂停、人工继续和分类权限边界已验证；真实模型全程无人干预尚未验证 |
| 睡眠/网络恢复及原生表格软件差异 | 列入 v0.1 真实平台回归 | 不重复付费请求；macOS Excel / Numbers 和 Linux LibreOffice 分别记录结果 |

## 发布判断

该报告证明跨平台真实链路能跑通，同时暴露可用性断点。rc.8 的本机工程回归与用户这次 rc.5 实装证据分开记录，详见[发布前工程审视](release-engineering-review.md)。新的 provider 恢复、翻译续传和表格回写仍需新候选包在 Mac 实装确认，不把 Windows 或模拟结果写成 Mac 通过，也不改写已冻结附件。
